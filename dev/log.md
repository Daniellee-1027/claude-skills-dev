# /dev log — 保存会话日志

## 执行流程

### 1. 收集会话信息

回顾当前会话中做了什么，整理以下信息：

- **做了什么**：本次会话的主要改动
- **关键决策**：为什么这么做（而不是那么做）
- **遗留问题**：下次需要处理的事情
- **改动的文件**：所有被修改/创建/删除的文件

如果信息不完整，简要询问用户补充。

### 2. 生成日志文件

文件路径：`docs/logs/{YYYY-MM-DD}-{简要描述}.md`

- 日期用今天的日期
- 简要描述用英文小写 + 连字符（如 `add-login`, `fix-search-bug`）
- 如果同一天已有日志，追加序号（如 `2026-03-13-add-login-2.md`）

### 3. 日志内容

```markdown
# Session: {简要描述}
Date: {YYYY-MM-DD}

## 做了什么
- {改动摘要1}
- {改动摘要2}

## 关键决策
- {决策1：为什么这么做}
- {决策2}

## 遗留问题
- {下次需要处理的1}
- {下次需要处理的2}
<!-- 如果没有遗留问题，写"无" -->

## 改动的文件
- {文件路径1}
- {文件路径2}
```

### 4. 完成

告诉用户日志已保存，显示文件路径。

## 注意事项

- 日志要**简洁**，不是复制完整对话
- 重点记录**决策和原因**，不是每一步操作
- 遗留问题要**具体**，下次打开就知道要做什么
- 如果会话中没有有意义的改动（比如只是问了个问题），可以不保存，告知用户

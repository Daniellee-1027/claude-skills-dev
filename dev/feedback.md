# /dev feedback — 记录人类测试反馈

## 执行流程

### 1. 收集反馈

用简单的语言逐步询问用户：

1. **你测试了什么功能？**
2. **发现了什么问题？**（或者：用起来感觉怎么样？）
3. **问题的具体表现是什么？**（比如：点了按钮没反应 / 显示的内容不对 / 速度很慢）
4. **你觉得应该怎样才对？**（期望行为）
5. **严重吗？**（完全不能用 / 能用但不方便 / 小问题）

### 2. 追加到 human-test-log.md

将反馈追加到 `docs/feedback/human-test-log.md`，格式：

```markdown
## {今天日期}

### 测试内容
{用户测试了什么}

### 发现的问题
- {问题1}
- {问题2}

### 整体感受
{用户的整体反馈}
```

### 3. 询问是否创建 Issue

对于每个具体问题，询问用户：

"这个问题要创建一个 issue 来跟踪吗？"

如果是 → 创建 `docs/issues/open/{描述性文件名}.md`：

```markdown
# Issue: {简短标题}

**日期**: {今天日期}
**来源**: 人类测试反馈
**严重程度**: {高/中/低}

## 描述
{问题描述}

## 期望行为
{应该怎样}

## 实际行为
{现在怎样}

## 复现步骤
{如果有的话}

## 状态
- [ ] 已确认
- [ ] 修复中
- [ ] 已修复
- [ ] 已验证
```

### 4. 检查是否涉及产品决策

如果反馈中涉及"应该这样做还是那样做"的选择：

- 询问用户的决定
- 记录到 `docs/feedback/decisions.md`：

```markdown
## {今天日期}: {决策标题}
**背景**：{为什么需要做这个决定}
**决定**：{最终选了什么}
**原因**：{为什么}
**影响**：{影响了哪些地方}
```

### 5. 完成

告诉用户：
- 反馈已记录到 `docs/feedback/human-test-log.md`
- 创建了 N 个 issue（如果有的话）
- 记录了 N 个产品决策（如果有的话）
- 建议下一步："要修复哪个问题？可以用 `/dev <修复描述>` 开始"
